1. APP OVERVIEW
================================================================================

App name (merchant-facing):  Offrefy  (see app/branding.ts)
Shopify app name (toml):     Volume Discount
Package name (npm):          offrefy

Purpose:
  A Shopify embedded admin app that lets merchants create "Quantity Breaks"
  (volume discount) campaigns. Discounts are applied at checkout via a single
  Shopify Function (automatic app discount) instead of creating one Shopify
  discount per campaign — bypassing Shopify's ~25 automatic discount limit.

Main features:
  - Create / edit / duplicate / archive volume discount campaigns
  - Tier-based pricing (% off, fixed amount, fixed price per unit)
  - Product scope: all products, specific products, variants, collections, groups
  - Quantity conditions: per-variant, per-product, per-collection, total-all
  - Customer targeting: everyone, logged-in, logged-in with tags
  - Product-page widget (theme app extension) with customizable colors/fonts
  - Countdown timer for promo windows
  - CSV import / export of offers
  - Storefront discount preview via app proxy calc endpoint
  - Flat DiscountRule table for O(1) cart lookup when metafield size exceeds limits

8. SERVICES LAYER (`app/services/`)
================================================================================

volumeDiscountFunctionSync.server.ts  ★ CENTRAL SYNC ORCHESTRATOR
  syncVolumeDiscountShop(admin, shop)
  Called after every campaign create/update/delete/activate.
  Steps:
    1. Load active campaigns from DB
    2. buildVolumeDiscountFunctionConfig() → JSON for Function metafield
    3. Ensure single DiscountAutomaticApp exists (VolumeDiscountShopState)
    4. Write metafields: volume_discount.input_variables, rule_source, campaigns*
    5. rebuildDiscountRulesForShop() → flat DiscountRule table
    6. syncShopStorefrontWidgetMetafield() → shop metafield for theme
    7. rebuildAndPersistStorefrontPayload() → DB cache for app proxy
    8. Purge legacy per-campaign discount nodes if needed

shopStorefrontMetafield.server.ts
  Writes shop-level metafield: volume_discount.storefront_widget (PUBLIC_READ)
  Ensures metafield definition exists. Used by theme Liquid + inline JSON fallback.

volumeDiscountStorefrontCache.server.ts

  rebuildAndPersistStorefrontPayload() — rebuild from campaigns + Admin API

volumeDiscountShopify.server.ts

12.1 volume-discount-fn  (PRIMARY DISCOUNT FUNCTION)
--------------------------------------------------------------------------------
Handle: volume-discount-fn
Type: Shopify Function (WASM)
Targets:
  cart.lines.discounts.generate.run   → src/run.js (export: cart-lines-discounts-generate-run)
  cart.lines.discounts.generate.fetch → src/fetch.js (network access for large catalogs)
Input variables metafield: volume_discount.input_variables
Capabilities: network_access = true

Source files:
  src/index.js          Entry, re-exports run + fetch handlers
  src/run.js            Main discount logic (~700 lines)
  src/input.graphql     GraphQL input query for run target
  src/fetch.graphql     GraphQL input query for fetch target
  src/fetch.js          Fetches rules from app proxy when metafield too large
  dist/function.wasm    Compiled output (deployed)

Logic summary (run.js):
  - Reads campaign rules from discount metafields (volume_discount.campaigns + shards)
  - Matches cart lines to campaigns by productId/variantId/scope
  - Applies quantity conditions (per-variant, per-product, etc.)
  - Picks highest qualifying tier (minQty threshold)
  - Applies percentage or fixed-amount discount per line
  - Customer type filtering (everyone / logged-in / tag-any)
  - Currency-aware fixed amount discounts

13. DATA FLOW (END-TO-END)
================================================================================

MERCHANT CREATES/EDITS OFFER (Admin)
  VolumeDiscountCreateView form
    → POST action (app.volume-discount.new or .$id)
    → parseVolumeDiscountForm()
    → prisma.volumeDiscountCampaign.create/update()
    → syncVolumeDiscountShop(admin, shop)
         ├── buildVolumeDiscountFunctionConfig() → metafield JSON
         ├── Shopify GraphQL: upsert DiscountAutomaticApp + metafields
         ├── rebuildDiscountRulesForShop() → DiscountRule table
         ├── syncShopStorefrontWidgetMetafield() → shop metafield
         └── rebuildAndPersistStorefrontPayload() → DB cache

STOREFRONT WIDGET RENDERS (Customer on product page)
  Theme block/embed loads volume-discount-storefront.js
    → GET /apps/volume-discount/widget-config?product_id=X&variant_id=Y
    → apps.volume-discount.widget-config.tsx loader
    → readStorefrontPayloadForServe() OR buildStorefrontWidgetForProduct()
    → Returns { version, campaigns: [...] }
    → JS renders tier buttons, updates price display, handles add-to-cart

CHECKOUT DISCOUNT APPLIES (Customer at cart/checkout)
  Shopify invokes volume-discount-fn (cart.lines.discounts.generate.run)
    → Reads rules from discount metafield (volume_discount.campaigns*)
    → If rules too large: fetch target calls POST /apps/volume-discount/cart-rules
    → Matches lines, computes tier discounts
    → Returns CartLinesDiscountsGenerateRunResult with discount candidates

DISCOUNT PREVIEW (Cart drawer / AJAX)
  Storefront JS POST /apps/volume-discount/calc
    → apps.volume-discount.calc.tsx
    → computeUnlimitedDiscountPreview(campaigns, body)
    → Returns calculated prices without Shopify discount activation

18. KEY DESIGN DECISIONS
================================================================================

1. ONE FUNCTION DISCOUNT PER SHOP
   All active campaigns share a single DiscountAutomaticApp. Config lives in
   metafields. Avoids Shopify's ~25 automatic discount limit.

2. DUAL RULE STORAGE
   - Metafield JSON: fast path inside WASM Function (no network)
   - DiscountRule DB table + cart-rules API: fallback when catalog exceeds metafield size
   Function has network_access=true to call app proxy at checkout.

3. STOREFRONT PAYLOAD CACHE
   VolumeDiscountStorefrontPayload table mirrors shop metafield JSON so app proxy
   can serve widget config without Admin API session on every request.

4. PER-PRODUCT WIDGET FETCH
   widget-config accepts product_id param to return one campaign instead of full
   catalog — critical for shops with 1000+ products.

5. FLAT DISCOUNT RULE INDEX
   DiscountRule rows keyed by (shop, productId) enable O(1) lookup at cart time
   instead of scanning all campaigns.

6. CAMPAIGN STATUS LIFECYCLE
   draft → active → archived. Only active campaigns sync to Shopify + storefront.

7. REACT ROUTER FILE ROUTES
   flatRoutes() convention — route file name maps directly to URL path.

8. LAZY-LOADED ADMIN COMPONENTS
   VolumeDiscountCreateView, OfferTypePreviewModal loaded via React.lazy()
   to reduce initial /app bundle size.
